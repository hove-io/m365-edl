Public service IPv4 EDLs

Listes IPv4 publiques générées et validées automatiquement depuis des sources officielles.

Microsoft 365 Common : les CIDR explicites du web service sont complétés uniquement par les A publics observés pour word.office.com, cible auditée du wildcard officiel *.office.com. La provenance DNS est conservée 24 heures ; aucun préfixe Azure ni /32 manuel n'est ajouté.

Teams Media / Direct Routing : seules les plages commerciales 52.112.0.0/14 et 52.120.0.0/14 sont acceptées. Les plages GCC High, DoD ou toute plage inattendue font échouer la publication.

Windows Update, Delivery Optimization et Intune : les familles FQDN officielles sont validées dans les sources Microsoft puis des cibles DNS auditées sont résolues à chaque exécution. L'EDL Intune conserve pendant 24 heures uniquement les IPv4 publiques réellement observées sous *.events.data.microsoft.com, y compris les diagnostics Windows et Configuration Manager explicitement documentés. Les cibles dynamiques prioritaires Intune, Windows Settings et Edge sont aussi observées depuis deux vues DNS françaises contrôlées, avec chaîne CNAME et grâce de 24 heures. Aucune IP de logs ni plage Azure globale n'est injectée manuellement.

Apple : les listes utilisent uniquement les A publics courants des FQDN présents dans la source Apple. Les services Device setup et Device management sont regroupés, tandis que les téléchargements Xcode sont isolés. Chaque EDL Apple conserve pendant 24 heures uniquement les IPv4 réellement observées via ses FQDN officiels, avec leur chaîne CNAME. Aucun 17.0.0.0/8 ni range CDN global n'est ajouté. Apple recommande d'exempter ces FQDN de l'inspection HTTPS.

GitHub Actions : la liste dédiée est alimentée uniquement par les FQDN *.actions.githubusercontent.com concrets publiés dans l'API Meta GitHub. Leurs A publics sont conservés 24 heures avec leur chaîne CNAME ; les CIDR Actions et Azure globaux ne sont jamais importés.
